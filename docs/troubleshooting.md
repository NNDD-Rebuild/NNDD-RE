# トラブルシューティング

よくある質問は[よくある質問](/NNDD-RE/faq/)にもまとめています。

## 動画の再生・ダウンロードと必要なツール

再生は、常に yt-dlp と FFmpeg なしで動作します。ダウンロードも、**既定の設定では外部ツールなし**で動作します。設定を変えたときだけ、外部ツールを使う方式に切り替わります。

設定 → DLリスト・ライブラリには、ダウンロードの方式を決める項目が2つあります。

| 「ネイティブHLSダウンロードを優先する」 | 「mux実装」 | ダウンロードの動作 |
|---|---|---|
| ON（既定） | mediabunny（既定） | アプリ内蔵の方式だけで動作します。yt-dlp も FFmpeg も不要です。失敗しても、yt-dlp には切り替わりません |
| ON | ffmpeg | 映像と音声の結合に FFmpeg を使います。内蔵の方式で失敗したときは、yt-dlp に切り替わります |
| OFF | （無関係） | 常に yt-dlp を使います |

音声のみのダウンロードは、「ネイティブHLSダウンロードを優先する」がONのときだけ使えます。OFFにしていると、エラーになります。

外部ツールの導入は[インストール・アップデート](/NNDD-RE/install/)を参照してください。

## Q. 動画がダウンロードできない

1. 設定 → DLリスト・ライブラリの2つの項目を確認します。既定のまま（ネイティブHLS: ON、mux実装: mediabunny）の場合、内蔵の方式で失敗した動画は、失敗として表示されます
2. 失敗を繰り返す場合は、次のどちらかを試してください。
   - 「mux実装」を「ffmpeg」にして、FFmpeg と yt-dlp を導入する（内蔵の方式で失敗したときに、yt-dlp で再試行します）
   - 「ネイティブHLSダウンロードを優先する」をOFFにして、yt-dlp を導入する
3. ログインしているかを確認します。接続診断（設定 → 接続診断）で、ニコニコ側のAPIに接続できているかを確認できます
4. コメント取得で「too many request」のエラーが出る場合は、ニコニコ側のアクセス制限です。設定 → DLリスト・ライブラリで、同時ダウンロード数を減らす、ダウンロード間のクールダウンを増やす、といった調整をしてください

## Q. 動画は視聴できるのに、ダウンロードだけ動かない

視聴は、ニコニコのサーバーから直接再生するため、yt-dlp も FFmpeg も使いません。ダウンロードは別の方式のため、動画によっては視聴できてもダウンロードに失敗することがあります。上の「動画がダウンロードできない」の手順を試してください。

## Q. ダウンロード済み動画の再生で、シークすると映像が固まる

アプリを再起動してください。改善しない場合は、ログを添えて[GitHubのIssue](https://github.com/NNDD-Rebuild/NNDD-RE/issues)で報告してください。

## Q. スマホや他のPCから、内蔵HTTPサーバーに接続できない

次の点を順に確認してください。

1. 設定 → 全般で、内蔵HTTPサーバーが起動しているか
2. 「待受範囲」が、「このPCのみ」になっていないか（他の端末から接続する場合は、「LAN内の他端末からのアクセスを許可」にして、サーバーを再起動します）
3. OSのファイアウォールが、ポート（初期値は12345）への接続を遮断していないか
4. IPアドレスや、PCの名前ではなく、別のドメイン名でアクセスしていないか（その場合は、「追加で許可するホスト名」に登録します）
5. URLの末尾が `/library` になっているか

詳しくは[内蔵HTTPサーバー・LAN共有](/NNDD-RE/http-server-integration/)を参照してください。

## Q. 不具合を報告したい

1. 設定 → ログで、ログレベルを「詳細」にします
2. 不具合が起きる操作を、もう一度行います
3. 設定 → ログの「ファイルを開く」で、ログファイルを開きます
4. [GitHubのIssue](https://github.com/NNDD-Rebuild/NNDD-RE/issues)に、操作の手順とログを書いて報告します（ログにアカウント情報が含まれていないか、確認してから貼ってください）

設定 → 情報の「パス情報」で、ログなどの保存先を確認できます。
