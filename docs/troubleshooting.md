# トラブルシューティング

## 動画の再生とダウンロード、必要なツールについて

再生（ストリーミング、デフォルト動作）は常に yt-dlp / FFmpeg 不要です。ダウンロードも**デフォルト設定では外部ツール不要**で動作しますが、設定次第で yt-dlp / FFmpeg を使う経路に切り替わります。

**再生（常に yt-dlp / FFmpeg 不要）**

```
WatchInfoHandler → 視聴ページ解析
       ↓
WatchSession     → HLSアクセス権取得（最高品質を自動選択）
       ↓
hls.js           → アプリ内に直接ストリーミング再生
```

設定のストリーミング再生モードにより挙動が変わります。いずれのモードも yt-dlp・FFmpeg は不要です。

- `native`（デフォルト）: hls.js が niconico CDN に直接アクセス
- `hls`: 内蔵HTTPプロキシ経由で再生
- `niconico`: ニコニコ公式プレイヤーを埋め込み表示（音声のみ再生は非対応）

**ダウンロード（デフォルトは外部ツール不要、設定でyt-dlp/FFmpeg利用に切替可能）**

```
DownloadManager.enqueue()
       ↓
[動画DL方式が既定の「ネイティブHLS優先」の場合]
NNDD-RE内蔵の実装がHLSセグメントを直接取得
       ↓
[mux実装が既定の「mediabunny」の場合]
mediabunny（JavaScript実装）がmp4へmux
       ↓
ライブラリへ登録・ファイル命名
```

- 設定 → DLリスト・ライブラリの「動画DL方式」「mux実装」がどちらも既定値（ネイティブHLS優先 / mediabunny）のままなら、通常のダウンロードは yt-dlp・FFmpeg どちらも使わずに完結します
- ネイティブHLS実装が失敗した場合のみ、自動的に yt-dlp へフォールバックします（この時だけ yt-dlp が必要になります）
- mux実装を「mediabunny」から「ffmpeg」に変更した場合は、その結合処理に FFmpeg が必要です（mediabunny失敗時のyt-dlpへの自動フォールバックはありません）
- 「ネイティブHLSダウンロードを優先する」をOFFにしている場合は、常に yt-dlp を使ってダウンロードします

## Q. 動画がダウンロードできない

まず設定 → DLリスト・ライブラリの「動画DL方式」「mux実装」が既定値のままか確認してください。既定のままでも失敗する動画（ネイティブHLS実装が対応していない形式等）では yt-dlp へのフォールバックが必要になるため、設定 → 外部ツール画面から yt-dlp / FFmpeg を導入すると解決することがあります。バイナリは `userData/bin/` 配下に保存されます。yt-dlpと同じディレクトリに置くことで、yt-dlpがFFmpegを自動検出します。

コメントのみダウンロード（`commentOnly: true`）の場合はこの動画DLステップ自体がスキップされ、yt-dlp/FFmpegは呼び出されません。

## Q. 動画は視聴できるのにダウンロードだけ動かない

視聴（デフォルトのストリーミング再生）は niconico CDN から `hls.js` で直接再生するため常に yt-dlp / FFmpeg は不要です。ダウンロードも既定設定では同様に外部ツール不要ですが、動画によってはネイティブHLS実装が対応できずダウンロードにだけ失敗することがあります。その場合は上記「動画がダウンロードできない」の手順で yt-dlp / FFmpeg を導入してください（フォールバック用のため、導入しておくと成功率が上がります）。

## Q. ダウンロード済み動画のローカル再生でシーク時に映像が固まる/落ちる

ローカルファイルの再生は内部的にループバックHTTP（`http://127.0.0.1:<ポート>/local/media`）経由で配信しています。稀にこの経路が使えない環境ではカスタムプロトコル（`nndd-re-local://`）へ自動的にフォールバックしますが、通常は意識する必要はありません。改善しない場合はアプリを再起動してください。
